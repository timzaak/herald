# 积分账户用户故事

> 角色定义以 [docs/user-stories/_roles.md](../_roles.md) 为准。

## 用户故事

### 故事 1：管理积分账户目录 US-CB-001

**优先级**: P0

**【用户故事】**
**作为**：Realm Admin（详见 [docs/user-stories/_roles.md](../_roles.md)）
**我希望**：在本 Realm 内创建、编辑、启用/禁用多个积分账户
**从而**：为不同业务线或应用群配置独立的积分账户目录与消费隔离边界

**【验收标准】**

> 验收标准只描述用户动作与可见结果，不写 API 路径、数据表、字段变更、技术实现步骤。

**场景 1：创建并管理积分账户**
```gherkin
Given Realm Admin 已登录管理后台并进入积分账户管理页
When 管理员创建一个新积分账户（填写名称、可选展示顺序）并保存
Then 该积分账户出现在本 Realm 的账户列表中，默认为启用状态
And 管理员可编辑其名称与展示顺序
And 注册/免费积分进入哪些积分账户由注册分发规则决定（规则集合可引用多个账户扇出发放），积分账户本身不携带"唯一注册接收账户"标记
```

**场景 2：禁用积分账户不影响已持有账户**
```gherkin
Given 某积分账户已存在且关联了套餐/积分包
When 管理员禁用该积分账户
Then 该积分账户不再对新用户可见可购
And 已持有该积分账户的用户仍可消费其剩余积分
```

### 故事 2：为积分账户绑定 Client App 覆盖集 US-CB-002

**优先级**: P0

**【用户故事】**
**作为**：Realm Admin（详见 [docs/user-stories/_roles.md](../_roles.md)）
**我希望**：为每个积分账户指定它覆盖的 Client App 集合
**从而**：限定只有被覆盖的 Client App 才能消费该积分账户内的积分

**【验收标准】**

**场景 1：绑定覆盖集**
```gherkin
Given 一个已创建的积分账户
When 管理员为其选择一个或多个 Client App 作为覆盖集并保存
Then 该积分账户显示已覆盖的 Client App 列表
And 至少绑定一个 Client App 才能保存成功
```

**场景 2：注册分发规则引用的账户也需显式配置覆盖集**
```gherkin
Given Realm 内某个积分账户被注册/免费积分分发规则引用为目标账户
When 管理员未为其配置任何 Client App 覆盖集
Then 该账户内的注册/免费积分不可被任何应用消费
And 管理员为其配置覆盖集后，仅被覆盖的应用可消费该账户积分
```

### 故事 3：为套餐/积分包配置积分分发规则 US-CB-003

**优先级**: P0

**【用户故事】**
**作为**：Realm Admin（详见 [docs/user-stories/_roles.md](../_roles.md)）
**我希望**：为每个可购买的套餐或积分包配置积分分发规则（每条规则指定一个目标积分账户）
**从而**：用户购买该套餐/积分包后，积分按规则进入对应积分账户（支持 0..N 条规则扇出，见 [multi-wallet-grant-rules.md](../../prd/billing/multi-wallet-grant-rules.md)）

**【验收标准】**

**场景 1：为套餐配置指向积分账户的分发规则**
```gherkin
Given 一个已创建的积分账户和一个已配置的套餐/积分包
When 管理员为该套餐/积分包添加一条指向此积分账户的分发规则并保存
Then 该套餐/积分包显示其分发规则指向的积分账户
And 一个积分账户可被多个套餐/积分包的规则引用
```

**场景 2：未配置积分规则的套餐仍可购买**
```gherkin
Given 某套餐/积分包未配置任何积分分发规则（如纯角色商品）
When 用户尝试购买该套餐/积分包
Then 购买可以正常完成
And 该次购买不发放积分（无积分规则即无积分入账），商品配置的其他权益（如角色）照常生效
```

### 故事 4：购买积分账户套餐/积分包 US-CB-004

**优先级**: P0

**【用户故事】**
**作为**：Regular User（详见 [docs/user-stories/_roles.md](../_roles.md)）
**我希望**：购买某个积分账户对应的套餐或积分包，积分进入该积分账户
**从而**：为特定应用群充值独立、隔离的积分

**【验收标准】**

**场景 1：购买并入账到账户池**
```gherkin
Given 用户已登录，且某积分账户对应的套餐/积分包可购
When 用户完成该套餐/积分包的支付
Then 用户获得该积分账户的积分，积分到账
And 该积分仅能被此积分账户覆盖的 Client App 消费
```

**场景 2：同时持有多个积分账户**
```gherkin
Given 用户已持有积分账户 A 的积分
When 用户再购买积分账户 B 对应的套餐/积分包并支付成功
Then 用户同时持有积分账户 A 与积分账户 B 两个独立积分账户
And 两个账户的余额互相独立、互不影响
```

### 故事 5：查看按账户分组的积分余额 US-CB-005

**优先级**: P0

**【用户故事】**
**作为**：Regular User（详见 [docs/user-stories/_roles.md](../_roles.md)）
**我希望**：在积分页面看到我持有的每个积分账户的独立余额，以及跨全部积分账户的合计
**从而**：清楚每个应用群可用积分和总体积分

**【验收标准】**

**场景 1：多积分账户余额展示**
```gherkin
Given 用户同时持有多个积分账户的积分
When 用户打开积分余额页
Then 页面按账户分组显示每个账户的余额（按积分类型分账户）
And 页面显示跨全部积分账户的积分合计
```

**场景 2：注册积分所在积分账户余额可见**
```gherkin
Given 用户持有注册/免费等系统发放的积分（位于注册分发规则引用的积分账户）
When 用户查看积分余额页
Then 该积分账户的余额与其他积分账户一并分组展示
```

### 故事 6：查看积分账户维度的交易历史 US-CB-006

**优先级**: P1

**【用户故事】**
**作为**：Regular User（详见 [docs/user-stories/_roles.md](../_roles.md)）
**我希望**：在交易历史中看到每笔交易所属的积分账户，并能按积分账户筛选
**从而**：核对每个积分账户的收支明细

**【验收标准】**

**场景 1：交易记录显示积分账户并支持筛选**
```gherkin
Given 用户有多个积分账户的积分收支记录
When 用户打开交易历史页
Then 每条记录显示其所属的积分账户
And 用户可按积分账户筛选交易记录
```

### 故事 7：SDK 按 Client App 跨积分账户消费 US-CB-007

**优先级**: P0

**【用户故事】**
**作为**：Third-Party App（详见 [docs/user-stories/_roles.md](../_roles.md)）
**我希望**：通过 SDK 消费积分时，系统按当前 Client App 自动从覆盖该应用的积分账户中扣减
**从而**：在不感知积分账户的情况下，按应用授权范围正确消费用户积分

**【验收标准】**

**场景 1：跨多个账户池消费**
```gherkin
Given 用户持有两个积分账户（积分账户 A、积分账户 B），两者都覆盖当前 Client App，且积分账户 A 内积分更早过期
When 第三方应用代表用户消费一定积分
Then 系统按过期时间优先，跨这两个账户池扣减，原子完成且不超额
```

**场景 2：无可用账户池或余额不足**
```gherkin
Given 用户名下没有任何覆盖当前 Client App 的账户池，或覆盖账户池合计余额不足
When 第三方应用代表用户消费积分
Then 系统拒绝消费并返回余额不足/无可用积分账户的明确提示
```

**场景 3：应用越权消费**
```gherkin
Given 某积分账户未覆盖当前 Client App
When 第三方应用尝试消费该账户池内的积分
Then 系统拒绝消费，该账户池不被扣减
```

### 故事 8：订阅生命周期按规则路由发放与回收 US-CB-008

> 本故事在 `points-grant-redesign` 后语义更新：订阅/免费周期积分的回收从"回收 ledger 行"改为"撤销配额权益"，已消费量随窗口滚动自然释放、不反向调整。`multi-wallet-grant-rules` 改版后，订阅不再绑定单一积分账户：首次发放按购买时捕获的规则快照路由，续费/升级按事件时点套餐当前启用规则集合路由（各期积分可能落入不同账户池）。

**优先级**: P0

**【用户故事】**
**作为**：Herald 系统（详见 [docs/user-stories/_roles.md](../_roles.md)）
**我希望**：订阅的首次发放、续费、升级、降级、取消、退款的积分都按套餐的分发规则准确定位到目标积分账户
**从而**：保证积分发放与回收始终回到正确的积分账户，不串账户

**【验收标准】**

**场景 1：续费按事件时点规则路由**
```gherkin
Given 用户已订阅某积分账户对应套餐的积分包，且首期积分已按购买时规则快照入账户池
When 订阅续费成功
Then 新一期积分按续费时点套餐当前启用的规则集合路由入账
And 规则未变化时进入与首期相同的账户池；规则已变化时按新规则入账（可能落入不同账户池）
```

**场景 2：取消/退款只回收本订阅发放的积分**
```gherkin
Given 用户已订阅某套餐对应的积分包
When 订阅被取消或发生退款
Then 系统按该订阅此前的发放记录定位账户池，仅回收该订阅发放的未使用会员积分（撤销配额权益），不影响其他账户池
```

**场景 3：升级回收旧套餐并发新套餐**
```gherkin
Given 用户已订阅某套餐对应的积分包，且当前周期会员积分已入账户池
When 用户在该订阅上升级到更高档套餐
Then 系统按旧套餐发放记录回收未使用的会员积分，并按新套餐当前规则发放新套餐积分
And 注册初始积分保留
And 不影响其他账户池
```

**场景 4：降级保留当前周期，下周期按新套餐规则发放**
```gherkin
Given 用户已订阅某套餐对应的积分包，且当前周期会员积分已发到账户池
When 用户在该订阅上降级到更低档套餐
Then 当前周期已发积分保留
And 下周期按新套餐的当前规则路由发放（规则不变时进入同一账户池）
And 不影响其他账户池
```
