# 履约模型扩展：买断与非续期订阅 用户故事

> 角色定义以 [统一角色定义](../_roles.md) 为准。

## 用户故事

### 故事 1：配置买断商品映射 [US-BM-001]

**优先级**: P0

**作为**：Realm Admin（详见 [统一角色定义](../_roles.md)）  
**我希望**：将 IAP 非消耗型商品映射为一次性购买加永久角色授予  
**从而**：销售一次付款、永久解锁的商品

**场景 1：保存买断映射**
```gherkin
Given Realm 已配置 IAP 渠道凭证和非消耗型商品
When 管理员创建一次性购买、永久角色授予且不配置积分的映射
Then 映射保存并启用为买断商品
```

**场景 2：与积分包并存**
```gherkin
Given 同一渠道有积分包和买断商品
When 管理员分别配置两种映射
Then 两个映射独立生效
```

### 故事 2：配置非续期订阅映射 [US-NR-001]

**优先级**: P0

**作为**：Realm Admin（详见 [统一角色定义](../_roles.md)）  
**我希望**：为 IAP 商品配置非续期订阅和固定服务期  
**从而**：销售不会自动续费的固定时长服务

**场景 1：保存非续期映射**
```gherkin
Given Realm 已配置 IAP 渠道凭证
When 管理员选择非续期订阅并填写服务期时长
Then 映射保存并启用
```

**场景 2：缺少服务期**
```gherkin
Given 管理员正在创建非续期订阅映射
When 未填写服务期时长就提交
Then 系统拒绝保存并提示服务期时长必填
```

### 故事 3：管理非续期订阅 [US-NR-002]

**优先级**: P1

**作为**：Realm Admin（详见 [统一角色定义](../_roles.md)）  
**我希望**：在订阅管理中区分非续期订阅  
**从而**：准确判断是否自动续费和何时到期

**场景 1：查看计费类型**
```gherkin
Given Realm 同时有自动续期和非续期订阅
When 管理员查看订阅列表或详情
Then 非续期订阅显示计费类型和服务期截止时间，且不显示自动续费信息
```

**场景 2：查看失效记录**
```gherkin
Given 非续期订阅已失效
When 管理员查看该订阅
Then 状态显示为 Expired 且变更历史包含失效记录
```

### 故事 4：购买买断商品 [US-BM-002]

**优先级**: P0

**作为**：Regular User（详见 [统一角色定义](../_roles.md)）  
**我希望**：购买买断商品后立即获得永久权益  
**从而**：无需订阅即可永久解锁功能

**场景 1：购买成功**
```gherkin
Given 用户在移动 App 完成买断商品购买
When Herald 校验购买凭证通过
Then 用户获得映射的永久角色且不发放未配置的积分
```

**场景 2：重复购买**
```gherkin
Given 用户已持有该买断商品的永久角色
When 用户再次购买同一商品
Then 系统拒绝购买并提示用户已拥有该权益
```

### 故事 5：恢复买断购买 [US-BM-003]

**优先级**: P0

**作为**：Regular User（详见 [统一角色定义](../_roles.md)）  
**我希望**：在换机或重装后恢复买断权益  
**从而**：已购权益不会丢失

**场景 1：恢复成功**
```gherkin
Given 用户曾购买买断商品
When App 提交同一交易的恢复购买凭证且校验通过
Then 系统补授永久角色且不重复发放权益
```

**场景 2：恢复凭证无效**
```gherkin
Given App 提交无效或不属于当前用户的恢复凭证
When Herald 校验该凭证
Then 系统拒绝补授并说明凭证无效或归属不符
```

### 故事 6：购买非续期订阅 [US-NR-003]

**优先级**: P0

**作为**：Regular User（详见 [统一角色定义](../_roles.md)）  
**我希望**：购买固定时长且不自动续费的服务  
**从而**：按需购买而不担心后续扣费

**场景 1：获得固定服务期**
```gherkin
Given 用户完成非续期订阅购买
When Herald 校验购买凭证通过
Then 用户获得带明确截止时间的有效订阅，且不会自动续费
```

**场景 2：到期后再次购买**
```gherkin
Given 用户的非续期订阅已失效
When 用户再次购买同一非续期商品
Then 用户获得新的固定服务期
```

### 故事 7：查询权益（非续期订阅与买断）[US-NR-004，买断部分对应 US-BM-004]

**优先级**: P1

**作为**：Third-party App（详见 [统一角色定义](../_roles.md)）  
**我希望**：查询非续期订阅，并通过角色判断买断权益  
**从而**：正确决定功能可见性

**场景 1：查询非续期订阅**
```gherkin
Given 用户持有非续期订阅
When 第三方应用查询用户订阅
Then 返回结果可识别非续期计费类型和服务期截止时间
```

**场景 2：查询买断权益**
```gherkin
Given 用户持有买断获得的永久角色
When 第三方应用查询用户订阅
Then 订阅结果不包含买断权益，应用通过角色或权限检查判断解锁
```

### 故事 8：退款或撤销买断 [US-BM-005]

**优先级**: P0

**作为**：Herald 系统（System Actor，详见 [统一角色定义](../_roles.md)）  
**我希望**：在买断交易被整笔退款或撤销（Stripe、Creem 为累计退款达到原支付金额）时回收支付来源的永久角色  
**从而**：退款后不保留支付产生的权益，商家的部分补偿不剥夺已购永久权益

**场景 1：回收支付来源角色**
```gherkin
Given 用户因买断购买持有支付授予的永久角色
When 商店确认该交易整笔退款或撤销，或支付渠道（Stripe、Creem）该笔支付的累计退款达到原支付金额
Then 系统回收该支付来源角色，保留管理员手工授予的同名角色
And 支付渠道的部分退款（累计未达全额，无论比例与笔数）保留该永久角色
```

**场景 2：重复事件**
```gherkin
Given 该笔退款或撤销已处理
When 系统再次收到同一事件
Then 系统不产生二次错误或额外回收
```

### 故事 9：处理非续期订阅生命周期 [US-NR-005]

**优先级**: P0

**作为**：Herald 系统（System Actor，详见 [统一角色定义](../_roles.md)）  
**我希望**：依据商店状态处理非续期订阅的失效和退款  
**从而**：权益状态与商店结果保持一致

**场景 1：Google 到期失效**
```gherkin
Given 用户持有 Google 非续期订阅
When 对账发现该订阅已过期
Then 系统将订阅置为 Expired 并记录变更历史
```

**场景 2：退款提前回收**
```gherkin
Given 用户持有未到期的非续期订阅
When 商店确认退款或作废购买
Then 系统提前终止该订阅权益，重复事件不产生二次错误
```

**场景 3：Apple 到期缺口**
```gherkin
Given 用户持有 Apple 非续期订阅且没有商店到期事件
When 服务期截止时间已过
Then 系统不会仅凭本地时间强制失效，该平台限制作为已接受风险记录
```
