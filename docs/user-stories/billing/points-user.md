### 故事 1：查看我的积分余额 [US-PU-001]

**优先级**: P0

**【用户故事】**
**作为**：Regular User（详见 [docs/user-stories/_roles.md](/docs/user-stories/_roles.md)）
**我希望**：查看自己的积分余额和累计统计（包括分类余额）
**从而**：了解当前积分状况

**【验收标准】**

> 验收标准只描述用户动作与可见结果，不写 API 路径、数据表、字段变更、技术实现步骤。

**场景 0：个人中心 Points 入口按积分包开通状态显示**
```gherkin
Given 我已登录 realm-1
And realm-1 存在可购买的积分产品
When 我打开个人中心
Then 侧边栏显示 "Points" 菜单
When realm-1 不存在可购买的积分产品
Then 侧边栏不显示 "Points" 菜单
And 我直接访问"我的积分"页面时被引导回个人资料页
```

**场景 1：查看个人积分余额（包含分类余额）**
```gherkin
Given 我已登录 realm-1
And realm-1 存在可购买的积分产品
And 我的用户 ID 是 user-1
And 我的积分账户有余额 5000
And 余额包含：充值积分 3000，会员积分 2000
When 我访问"我的积分"页面
Then 我看到我的积分余额卡片
And 卡片显示：
  | 字段         | 值         |
  | 总余额       | 5000       |
  | 充值积分余额 | 3000       |
  | 会员积分余额 | 2000       |
  | 单位         | points     |
  | 累计充值积分 | 8000       |
  | 累计会员积分 | 5000       |
  | 累计消耗     | 8000       |
  | 账户状态     | active     |
  | 最后更新时间 | 2026-03-13 12:00 |
```

**场景 2：余额实时更新（显示分类变化）**
```gherkin
Given 我已登录
And 我的积分余额是 5000
And 余额包含：充值积分 3000（永久有效），会员积分 2000（2026-04-15 过期，先到期）
When 我通过第三方应用消耗 100 积分
Then 我的余额卡片立即更新为 4900
And 会员积分余额更新为 1900（消费顺序按过期时间优先，先扣先到期的会员积分）
And 充值积分余额保持 3000
And 不需要刷新页面
```

**场景 3：查看账户状态**
```gherkin
Given 我已登录
And 我的积分账户状态是 "frozen"
When 我访问"我的积分"页面
Then 我看到账户状态显示为"已冻结"
And 我无法进行积分消耗操作
```

**场景 4：余额不足提示（显示分类余额）**
```gherkin
Given 我已登录
And 我的积分余额是 50
And 余额包含：充值积分 50，会员积分 0
When 我尝试消耗 100 积分
Then 我看到错误消息："积分不足，当前余额：50（充值积分：50，会员积分：0）"
And 操作未执行
```

**场景 5：查看积分单位说明**
```gherkin
Given 我已登录
When 我访问"我的积分"页面
Then 我看到积分单位为 "points"
And 我看到积分单位的说明："积分是系统的虚拟货币，可用于消耗第三方应用的服务"
```

### 故事 4：按时使用本期积分（不受分发延迟影响） [US-PU-009]

> 本故事的前提（预发 + 分发延迟）已被 `US-PU-010` 的懒发放/滚动窗口模型取代。保留原文仅作历史参考，产品意图以 `US-PU-010` 为准。

**优先级**: P0

**【用户故事】**
**作为**：Regular User（详见 [docs/user-stories/_roles.md](/docs/user-stories/_roles.md)）
**我希望**：每个订阅周期开始时就能使用本期积分，即使系统实际发放存在延迟
**从而**：不会因为系统分发延迟而在应得积分的时间点无积分可用

**【验收标准】**

> 验收标准只描述用户动作与可见结果，不写 API 路径、数据表、字段变更、技术实现步骤。

**场景 1：周期开始时本期积分已可用**
```gherkin
Given 我订阅了月付套餐
And 本期周期从 2026-04-01 00:00 开始
When 时间到达 2026-04-01 00:00（周期开始）
Then 我立即可消费本期发放的积分
And 即使本期积分的实际到账因系统延迟发生在周期开始之后，我在周期开始时仍能使用
```

**场景 2：续费延迟不造成积分真空**
```gherkin
Given 我的上一期积分将在本期周期开始时过期
And 支付平台的续费通知存在延迟
When 本期周期开始
Then 我本期积分已就绪可消费
And 我不会经历"旧积分已过期、新积分未到账"的真空期
```

**场景 2.1：后台任务未及时运行时，请求时同步兑现**
```gherkin
Given 我的上一期积分将在本期周期开始时过期
And 支付平台的续费通知尚未到达
And 系统的预发任务或生效任务尚未及时运行
When 本期周期已经开始
And 我查看积分余额或发起积分消费
Then 系统同步确认我本期应得的订阅积分
And 本期积分立即计入可用余额并可被消费
And 我不会因为后台任务延迟而拿不到本期积分
```

**场景 3：预先发放的积分在生效前不可见、不可消费**
```gherkin
Given 系统在本期周期开始前已预先发放本期积分（周期尚未开始）
When 我在 2026-03-31（周期开始前）查看余额或尝试消费
Then 预先发放的本期积分尚未生效、对我不可见，不计入我的余额、不可消费
When 时间到达 2026-04-01（周期开始）
Then 该积分变为可见且可消费
```

**场景 4：续费失败时预发积分被回收，我不持有未支付积分**
```gherkin
Given 系统已在本期周期开始前预先发放本期订阅积分
And 本期周期已开始，该积分对我可见、可消费
When 我的订阅续费最终被判定失败或取消
Then 系统回收本期预发但未支付的积分
And 我不持有未支付的积分
And 该回收不对普通用户展示为过期或回收的积分（对普通用户无感）
```

### 故事 5：滚动窗口额度与充值余额的可用性体验 [US-PU-010]

> 本故事承载"积分发放策略重设计（points-grant-redesign）"的新模型意图；其前提（懒发放、滚动窗口、超额转充值余额）取代了故事 4（US-PU-009）基于"预发 + 分发延迟"的旧前提。

**优先级**: P0

**【用户故事】**
**作为**：Regular User（详见 [docs/user-stories/_roles.md](/docs/user-stories/_roles.md)）
**我希望**：我的订阅额度按滚动时间窗口实时可用（周期中途加入即得、多时间窗限额、超额自动用充值余额），并清晰看到窗口剩余额度与充值余额
**从而**：不会因为系统发放延迟拿不到额度，不会因单个窗口耗尽就被打断，并能直观了解额度恢复时间

**【验收标准】**

> 验收标准只描述用户动作与可见结果，不写 API 路径、数据表、字段变更、技术实现步骤。

**场景 1：周期中途订阅，首次使用即得额度**
```gherkin
Given 本订阅周期已经开始（例如 2026-06-10 开始的月度周期）
And 我在 2026-06-20 才新订阅该套餐（周期中途加入）
And 系统没有为我提前发放任何额度
When 我在订阅后首次查看积分余额或首次消费
Then 我立即获得当前可用的订阅额度
And 我不需要等到下一个周期，也不依赖系统后台的预先发放
```

**场景 2：多时间窗滚动限额取最小值**
```gherkin
Given 我的订阅额度配置了多个时间窗限额（5 小时窗 500、周窗 5000、月窗 20000）
And 我在最近 5 小时内已用满 5 小时窗额度（已用 500）
When 我查看当前可用订阅额度
Then 当前可用订阅额度为各时间窗剩余中的最小值
And 由于 5 小时窗已用满，当前可用订阅额度为 0（尽管周窗和月窗仍有大量剩余）
```

**场景 3：窗口额度耗尽时超额自动用充值余额**
```gherkin
Given 我当前订阅窗口可用额度为 100
And 我有充值余额 1000
When 我消费 300 积分
Then 系统先扣完订阅窗口额度 100
And 剩余 200 自动从充值余额扣减
And 操作一次性成功，我不需要分两次操作
And 我看到订阅窗口额度降为 0、充值余额降为 800
```

**场景 4：窗口额度与充值余额合计不足时整体拒绝**
```gherkin
Given 我当前订阅窗口可用额度为 50
And 我的充值余额为 100
When 我尝试消费 300 积分
Then 系统拒绝本次消费
And 操作未执行，我的额度未被部分扣减
And 我看到提示说明当前可用额度（订阅窗口 50 + 充值 100 = 150）不足以完成本次消费
```

**场景 5：查看窗口剩余额度与充值余额（双展示）**
```gherkin
Given 我的订阅额度配置了 5 小时窗 500、周窗 5000
And 我在对应窗口内已使用部分额度
When 我访问"我的积分"页面
Then 我看到订阅额度按时间窗分别展示剩余额度与恢复时间（例如"5 小时窗：剩余 200，约 3 小时后恢复"）
And 我看到充值余额单独展示
And 我看到当前可消费总额 = 各窗口剩余的最小值 + 充值余额
```
