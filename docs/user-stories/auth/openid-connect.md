# 第三方应用开发者 用户故事（OpenID Connect 最小兼容层）

> 角色定义见 [docs/user-stories/_roles.md](/docs/user-stories/_roles.md)

**故事范围**: US-OC-001 ~ US-OC-004

---

## 故事 1：通过 issuer 自动发现 OIDC 配置 [US-OC-001]

**优先级**: P0

**【用户故事】**
**作为**：第三方应用开发者（详见 [docs/user-stories/_roles.md](/docs/user-stories/_roles.md)）
**我希望**：在我的应用或现成工具中只填一个 Herald issuer 地址，即可自动发现登录端点、令牌端点和验签公钥位置
**从而**：无需阅读 Herald 私有接入文档、无需集成 Herald SDK，即可按标准 OIDC 方式完成接入配置

**【验收标准】**

**场景 1：发现成功**
```gherkin
Given 某个 Realm 已存在且已注册 Client App
When 开发者在标准 OIDC 客户端配置中填入该 Realm 的 issuer 地址并保存
Then 客户端自动获得该 Realm 的标准 OIDC 配置（授权端点、令牌端点、用户信息端点、验签公钥位置），无需手工逐项填写
```

**场景 2：issuer 无效**
```gherkin
Given 开发者填入的 issuer 指向不存在的 Realm
When 客户端尝试发现配置
Then 发现失败并返回明确错误，不返回任何误导性的部分配置
```

## 故事 2：标准 OIDC 客户端完成登录并获得可本地验签的身份令牌 [US-OC-002]

**优先级**: P0

**【用户故事】**
**作为**：第三方应用开发者（使用 Grafana、Vault 等现成标准 OIDC 客户端的集成方）
**我希望**：标准 OIDC 客户端走授权码流程完成用户登录后，获得带签名的身份令牌（id_token），并用 Herald 公开的公钥在本地完成验签
**从而**：现成工具零代码改动接入 Herald 账号体系，Herald 成为这些工具的标准登录选项

**【验收标准】**

**场景 1：标准客户端登录成功**
```gherkin
Given 用户在某 Realm 拥有正常状态账号，标准 OIDC 客户端已按故事 1 完成 issuer 配置
When 用户在该客户端点击登录，跳转到 Herald 登录页完成认证（含 TOTP、Passkey 等既有二次认证，如已启用）
Then 客户端获得身份令牌，本地验签通过后显示该用户的稳定身份标识与邮箱，全程未使用 Herald SDK
```

**场景 2：账号被禁用**
```gherkin
Given 用户账号处于禁用状态
When 用户尝试经标准 OIDC 客户端登录
Then 登录被拒绝，客户端不会获得任何令牌
```

**场景 3：回调地址不在白名单**
```gherkin
Given 该 Client App 配置了 redirect_uri 白名单
When 客户端使用白名单之外的回调地址发起登录
Then Herald 拒绝该次授权，不进入登录流程（沿用既有白名单精确匹配规则）
```

## 故事 3：获取已登录用户的身份资料 [US-OC-003]

**优先级**: P0

**【用户故事】**
**作为**：第三方应用开发者
**我希望**：应用用登录获得的访问令牌向 Herald 查询当前用户的标准身份资料（稳定标识、邮箱、昵称）
**从而**：应用内展示用户身份并做个性化，而不必理解 Herald 私有接口

**【验收标准】**

**场景 1：查询成功**
```gherkin
Given 客户端经携带 openid 语义的授权流程持有该用户的有效访问令牌
When 应用携带访问令牌查询用户信息
Then 返回该用户的标准身份资料：稳定身份标识、邮箱与邮箱验证状态、昵称
```

**场景 2：访问令牌无效**
```gherkin
Given 访问令牌已过期、被撤销或不属于该用户
When 应用携带该令牌查询用户信息
Then 返回未授权错误，不返回任何用户资料
```

**场景 3：授权流程未请求 openid 语义**
```gherkin
Given 访问令牌来自不含 openid 语义的授权流程
When 应用携带该令牌查询用户信息
Then 请求被拒绝，不返回任何用户资料——身份资料只服务 openid 语义授权的凭证
```

**场景 4：邮箱未验证如实呈现**
```gherkin
Given 用户的邮箱尚未完成验证
When 应用查询用户信息
Then 邮箱验证状态如实显示为未验证，不会虚报为已验证
```

## 故事 4：签名公钥轮换对客户端透明 [US-OC-004]

**优先级**: P1

**【用户故事】**
**作为**：第三方应用开发者
**我希望**：Herald 轮换身份令牌签名密钥时，客户端通过公开的验签公钥自动适配
**从而**：密钥轮换不会造成第三方登录中断，我无需重新配置客户端

**【验收标准】**

**场景 1：轮换后新令牌可验签**
```gherkin
Given 客户端已按故事 1 正常接入
When Herald 轮换签名密钥后用户再次登录
Then 新签发的身份令牌仍可被客户端自动验签通过，登录持续可用
```

**场景 2：轮换重叠期旧令牌兼容**
```gherkin
Given 轮换前签发、仍在有效期内的身份令牌
When 客户端在轮换后的合理重叠期内对其验签
Then 验签仍可通过，不出现既有客户端大面积验签失败
```
