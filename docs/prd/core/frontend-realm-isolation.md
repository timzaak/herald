# Realm 入口与会话隔离

同一浏览器可同时登录不同 realm。每个标签的租户身份由访问入口确定，另一 realm 的登录、退出或刷新不得改变当前标签的租户、用户身份和数据。支持主域名与已绑定自定义域名两种入口。

## 2. 范围界定

### 2.1 包含功能

- 主域名下带 `/{realmId}` 前缀的租户入口：登录、管理后台、用户中心和订阅页面
- 已绑定自定义域名下无前缀的租户入口（同一产品树的镜像路由）
- 标签级会话与数据隔离：身份确定、用户状态、登录凭据、登录事务、私有数据缓存、请求重试与异步结果
- 从旧共享认证快照到按 realm 保存凭据的兼容过渡

### 2.2 不包含功能 (Out of Scope)

- 跨域单点登录（主域名与自定义域名属于不同来源，不自动共享浏览器登录状态）
- 同 realm 多标签的凭据轮换协调
- 控制台与用户中心的独立产品会话（属后续独立需求）

### 2.3 依赖项

- 自定义域名的绑定关系与解析门控（`cname_verified`/`tls_ready` 仅经受信代理确认，见 `docs/prd/core/realm-custom-domain.md` §2.3）
- OAuth 授权码流与 PKCE 登录事务（见 `docs/prd/auth/oauth.md` §4.1）

## 4. 业务规则与状态

### 4.1 业务规则

**入口确定**：

| 入口 | Realm 确定方式 | 页面地址示例 |
| --- | --- | --- |
| 主域名 | URL 中的 `/{realmId}` | `https://auth.fornetcode.com/oncewise/manage/settings` |
| 已绑定自定义域名 | 服务端确认的域名绑定关系 | `https://login.example.com/manage/settings` |

- 主域名下的租户页面统一保留 realm 前缀，包括登录、管理、用户中心和订阅页面。站内导航、登录回跳、刷新及复制链接均保持该规则。
- 自定义域名下的租户页面使用无 realm 前缀的路径。域名绑定关系决定唯一 realm，浏览器保存的登录状态不得覆盖它。
- 自定义域名收到与绑定 realm 相同的路径前缀时，规范化为无前缀地址；收到其他 realm 的前缀时，拒绝访问。
- 域名绑定解析异常时停止会话恢复，显示错误，不回退到其他 realm。
- 主域名下缺少 realm 的受保护地址，例如 `/manage/settings`，提示缺少租户信息，不根据上次登录记录猜测 realm。
- 平台创建新 realm 的入口仅在主域名提供；自定义域名继续支持本 realm 的账号注册。

**会话与数据边界**：

入口 realm 与登录会话的 realm 必须一致，受保护页面还须满足对应产品和权限要求。会话不匹配时，不得显示其他 realm 的身份或数据。

| 对象 | 隔离要求 |
| --- | --- |
| 当前标签 | 导航、会话恢复、访问检查和页面展示使用同一个入口 realm |
| 用户状态 | 当前用户、权限和认证状态保留在标签内，不从同源共享的认证快照恢复 |
| 登录凭据 | 按 realm 保存；恢复时由服务端确认用户、realm 和产品身份 |
| 登录事务 | 按标签隔离，并绑定 realm、客户端、回跳地址和有效期；PKCE 事务有效期为 300 秒 |
| 私有数据缓存 | realm、账号、产品或权限变化时取消旧查询并清除旧缓存，防止旧身份数据继续展示 |
| 请求与重试 | 始终使用发起请求时的身份；不得借用切换后的其他身份重试 |
| 异步结果 | 旧身份的迟到响应不得覆盖新身份的状态或凭据 |
| 退出 | 只撤销并清理目标 realm 的会话，不影响其他 realm 的凭据及登录事务 |

访问公共登录、授权同意或法律页面，不应仅因进入该页面而切换已有会话的产品身份。

**兼容规则**：

- 停止使用旧共享认证快照中的 realm、用户和权限确定当前身份；保留按 realm 保存的有效凭据。
- 旧无前缀链接只有在当前标签已具有可信 realm 上下文时才能转换；缺少该上下文时提示补充 realm。
- 旧登录事务缺少 realm 或标签归属时，要求重新开始登录。

### 4.2 关键状态与异常

- **缺少租户信息页**：主域名受保护地址缺 realm 前缀时进入的提示状态；无重试入口（重试无法改变地址），仅提示补全 realm 后重新进入
- **域名解析异常页**：自定义域名 Host 解析返回非"未绑定"结果时的错误状态；会话恢复停止，不回退其他 realm
- **登录事务失效**：PKCE 事务超过有效期或缺少 realm 绑定而作废；此后第二因子完成也要求重新开始登录，不静默继续

## 5. 验收目标

1. 同一浏览器分别打开 oncewise 和 admin 标签，任意顺序登录、刷新、切换菜单或复制地址，两个标签均保持各自的 realm。
2. admin 退出后刷新 oncewise 设置页，仍恢复 oncewise 会话；admin 保持退出。反向操作同样成立。
3. 直接打开 `/oncewise/manage/settings`，即使浏览器曾登录 admin，也只使用 oncewise 身份；无法恢复时进入 oncewise 登录页。
4. 已绑定自定义域名下的管理、用户中心和订阅页面，首次打开与刷新均保持绑定 realm，站内链接不添加 realm 前缀。
5. 自定义域名下同 realm 前缀被规范化，其他 realm 前缀被拒绝；域名解析异常时不恢复其他 realm 会话。
6. 同一标签切换 realm 或账号后，不展示旧身份的资料、权限、功能、通行密钥或钱包数据。
7. 不同 realm 在不同标签同时进行登录、二次验证或 OAuth 流程，刷新或退出其中一个不改变另一个的登录事务。
8. 旧身份的状态查询、授权码交换或请求重试延迟完成时，不覆盖新身份，也不使用新身份凭据重放旧请求。
9. 主域名缺少 realm 的受保护链接显示明确提示，不自动进入最近登录 realm 的页面。

## 6. 边界与约束

**适用性**: 适用（API 与前端/交互边界合并陈述）

**API / 集成边界:**

- 本需求以前端路由与会话管理为实现面，不新增独立产品 API；自定义域名入口判定依赖的域名绑定查询能力及其安全语义（仅 Host 头、未命中即 404、受信代理门控）由 realm-custom-domain PRD §2.3 承载
- 按 realm 分槽保存凭据的存储契约（含旧共享 key 的废弃）由前端认证层与 SDK 承载，详见技术设计

**前端 / 交互边界:**

- 平台自助创建新 realm 的入口（signup CTA）仅在主域名渲染；自定义域名渲染本 realm 的注册入口
- 缺少租户信息页与域名解析异常页的交互口径见 §4.2；错误提示页不提供重试按钮
- 路由树（真实树 / 镜像树 / 公共页三组）与入口解析的实现约定见 `frontend/README.md`

## 7. 已确认决策

> 本节只收录当前有效的产品级取舍，规则正文只在 §4 定义，此处不复述。

- **DEC-frontend-realm-isolation-001｜主域名仅凭 URL 前缀确定租户身份**：不持久化"最近访问的 realm"记忆，也不凭浏览器共享登录状态推断 realm。理由：共享快照会让任一标签的登录、退出或 realm 切换重定义同源所有标签的租户身份，两个 realm 无法在同一浏览器共存。重开条件：出现服务端驱动的入口发现机制且能保证标签级身份不被共享状态覆盖
- **DEC-frontend-realm-isolation-002｜自定义域名 Host 解析每页面会话一次且 fail-closed**：解析结果除"未绑定（视为主域名）"外的一切失败均停止会话恢复，不回退其他 realm。理由：解析失败时静默回退会让浏览器保存的登录状态决定租户身份，违背入口确定性。重开条件：无
- **DEC-frontend-realm-isolation-003｜待处理 PKCE 事务仅存于 sessionStorage 并绑定 realm 与标签，有效期与后端授权状态 TTL 对齐**（实现层）。理由：第二因子在事务过期后完成应显式失败并重新登录，而非静默继续到无法完成的回调。重开条件：无
- **DEC-frontend-realm-isolation-004｜平台自助创建新 realm 的入口仅在主域名提供**：自定义域名仅保留本 realm 的注册。理由：自定义域名绑定唯一 realm，在其上创建其他 realm 与入口语义冲突。重开条件：无
