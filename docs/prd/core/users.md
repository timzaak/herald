## 2. 范围界定

### 2.1 包含功能

- 用户列表展示（分页、筛选）
- 创建用户（邮箱、密码、昵称、状态、角色分配）
- 编辑用户（昵称、状态；邮箱只读展示）
- 删除用户（需要二次确认）
- 重置密码（系统自动生成 16 位随机密码）
- 用户状态管理（启用/禁用）
- 个人资料编辑（昵称）
- 修改个人密码（带密码强度指示器）
- 用户头像下拉菜单（Profile、Security 入口）

### 2.2 不包含功能 (Out of Scope)

- 用户批量导入导出（优先级较低，后续版本考虑）
- 用户审计日志（需要审计日志系统支持）
- 用户活动历史（需要活动历史系统支持，如登录和操作记录）
- 用户头像上传（前端存储限制，后续版本考虑）
- 密码强度增强（当前仅验证长度 >= 8，未来需增加大小写字母、数字、特殊字符的强度要求）

### 2.3 依赖项

- 用户认证系统 — 提供登录和会话管理
- 权限管理系统 — 提供 RBAC 权限检查
- 角色系统 — 支持用户角色分配（realm-admin、user）

## 3. 需求概述

### 3.1 功能描述

在 Herald 管理后台的左侧导航栏添加 Users 菜单项，用于展示和管理系统中的用户列表。同时为所有已登录用户提供个人资料管理和密码修改功能。管理员可通过用户列表对 Realm 内用户进行完整的生命周期管理（创建、编辑、重置密码、禁用、删除），普通用户可通过个人中心管理自身资料和密码。

### 3.2 关键特性

- 管理员用户列表 CRUD 与密码重置
- 个人资料查看与编辑（昵称）
- 个人密码修改（带密码强度指示器）
- 用户角色分配与权限控制
- 用户直接权限管理（分配/移除/查询有效权限）
- 管理后台用户头像下拉菜单入口
- Realm 数据隔离

## 4. 业务规则与状态

### 4.1 业务规则

- **Realm 数据隔离**：Realm Admin 只能访问自己 Realm 的用户，不能访问其他 Realm 的用户资源
- **角色分配约束**：创建用户时可不分配角色（无角色用户不持有任何权限，后续可通过角色分配端点补充分配，SDK ext API 即按无角色用户创建）；所有传入角色必须存在于目标 Realm。持 `roles.manage` 的调用方可分配任意角色（其中指派 "user" 以外的内置角色还受防提权校验约束，见 Permissions PRD）；未持 `roles.manage` 的调用方仅能创建无角色或仅含 "user" 内置角色的用户
- **角色管理**：角色通过独立端点 `PUT /api/users/{realmId}/{userId}/roles` 管理，编辑用户时角色字段为只读展示（需要 `users.view` + `roles.manage` 权限，详见 Permissions PRD）
- **编辑时密码不可变**：编辑用户时密码字段不显示
- **邮箱只读**：用户邮箱在创建后不可修改。
- **重置密码规则**：管理员重置密码时不允许手动输入，密码由后端自动生成（16 位，包含大小写字母、数字和特殊字符 `!@#$%^&*`）；重置成功后向管理员展示新密码并提供复制功能。
- **会话联动撤销**：管理端重置密码、删除用户，以及用户自行修改密码，均联动撤销该用户的浏览器会话（重置/删除撤销全部；自行改密撤销除当前会话外的全部）——超出显式踢出（kickoff）的联动撤销面，属实现既定行为。
- **删除二次确认**：删除用户操作需要二次确认
- **用户状态管理**：支持启用/禁用用户；被禁用的用户无法登录，登录失败统一返回防枚举文案 "email not verified or account not active"
- **权限层级**：`users.manage` 用于创建、更新、删除、重置密码操作（隐含 view）；`users.view` 仅用于查看用户列表
- **导航可见性**：Users 菜单仅对拥有对应权限的用户可见

### 4.2 关键状态与异常

- **用户状态枚举**：用户可处于以下状态，状态影响登录能力
  - `WaitVerified(0)`：等待验证
  - `Normal(1)`：正常
  - `Forbidden(2)`：禁用
  - `Deleted(3)`：已注销（匿名化终态，不可恢复）
- **密码强度反馈**：修改密码时提供实时密码强度指示器（弱/中/强）和改进建议提示
- **重置密码结果展示**：重置成功后显示新密码并提示管理员安全传达给用户
- **删除确认**：删除操作弹出确认对话框，确认后执行删除

## 5. 功能需求

### 5.1 核心需求

- 管理员可在用户列表页面查看、创建、编辑、删除用户，重置用户密码，管理用户状态，管理用户直接权限（分配/移除/查询有效权限）
- 管理员可通过用户头像下拉菜单快速访问个人 Profile 和 Security 页面
- 普通用户可查看个人资料（邮箱只读、状态只读、昵称可编辑）
- 普通用户可修改个人密码（修改属敏感操作，需先完成 reauth 身份验证——密码、TOTP、Passkey 三因素之一，验证通过后签发与操作绑定的短时票据，凭票据提交修改；密码是 reauth 因素之一，用户感知仍是"验证身份后修改密码"；新密码需符合密码策略并确认一致）
- 用户列表支持分页展示和基本筛选

### 5.2 验收目标

- 拥有 `users.manage` 权限的管理员可完整执行用户 CRUD 与密码重置操作
- 拥有 `users.view` 权限的用户仅可查看用户列表，无法执行修改操作
- 普通用户可成功修改自身昵称和密码
- 被禁用用户尝试登录时收到明确的禁用提示
- 重置密码后管理员能看到新密码并复制
- 删除用户时必须经过二次确认
- 所有操作在 Realm 隔离边界内完成，跨 Realm 访问被拒绝

## 6. API 相关约束

**适用性**: 适用

- 用户管理接口能力范围包括：用户查询（分页、筛选）、用户创建、用户编辑、用户删除、密码重置、用户状态变更、用户直接权限管理（分配/移除/查询有效权限）
- 个人资料接口能力范围包括：查看个人资料、修改昵称、修改密码
- 所有接口必须遵守 Realm 数据隔离原则，即用户只能访问所属 Realm 的数据
- 访问控制基于 `resource.action` 权限模型：`users.view`（查看）、`users.manage`（创建/更新/删除/重置密码，隐含 view）
- 敏感操作（删除用户、重置密码）需经过权限校验
- 密码相关接口需脱敏处理，不可返回明文密码
- 详细接口契约、验证规则和错误模型应在技术设计或接口文档中维护

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：管理后台左侧导航栏 Users 菜单项（权限控制可见性）；顶部 Header 用户头像下拉菜单提供 Profile 和 Security 入口
- **用户列表页面**：展示用户基本信息（ID、Email、Nickname、Status、Created At）；右上角提供 "Add User" 按钮；操作列提供 Edit、Reset Password、Delete 按钮
- **创建用户**：通过对话框表单实现，包含 Email（必填）、Password（创建时必填，最小 8 位）、Nickname（可选，最大 50 字符）、Status（默认 Normal）、Roles（可选，可不分配；不分配则创建无角色用户）字段
- **编辑用户**：复用创建对话框，密码字段隐藏，角色字段只读
- **重置密码交互**：点击确认后执行，成功后展示新密码并提供复制按钮
- **删除交互**：弹出确认对话框，确认后执行
- **个人资料页面**：Email 和 Status 为只读，Nickname 可编辑
- **修改密码页面**：包含当前密码、新密码、确认密码三个字段；当前密码用作 reauth 凭据（后端支持密码/TOTP/Passkey 三因素完成 reauth，验证后签发操作绑定的短时票据）；实时密码强度指示器（弱/中/强，颜色条反馈）；密码改进建议提示
- **权限可见性**：不同权限的用户看到的操作按钮和数据范围不同；无管理权限的用户无法看到管理后台，被重定向到个人中心

## 8. 已确认决策

### 8.1 已确认决策

- 用户管理采用 `resource.action` 权限模型，而非基于角色的硬编码权限检查
- 重置密码由后端自动生成，不允许管理员手动指定
- 编辑用户时不支持修改角色和密码；角色通过独立端点 `PUT /api/users/{realmId}/{userId}/roles` 管理
- 邮箱在用户创建后不可更改
