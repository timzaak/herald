## 2. 范围界定

### 2.1 包含功能

- **协议承载与版本化**：用户协议与隐私政策的承载、版本管理；采用「平台默认模板 + per-realm 覆盖」作用域；协议正文与版本存储于专用版本表（append-only，承载平台默认模板、per-realm 覆盖与历史留存），管理界面承载于 Settings 页面新增的协议 Tab。
- **平台默认协议模板正文**：提供平台默认模板的《用户协议》与《隐私政策》正文初稿，正式定稿需法务审阅。
- **同意记录与闸门**：注册即同意（注册提交即表示同意当前生效版本）、登录即同意（登录时若同意缺失或版本过期，随登录提交的同意被记录为重新同意；同意已是最新版本时登录不产生新的同意记录）、协议版本变更后触发重新同意；拒绝同意则限制核心功能。
- **协议更新与版本管理**：用户协议与隐私政策各自独立版本化；每次发布产生新版本；历史版本留存以供审计追溯；发布即生效；Realm 发布/回退与平台默认模板更新均构成版本变更并触发重新同意。
- **协议查看**：用户随时可查看所属 Realm 当前生效的用户协议与隐私政策及其版本信息（含注册/登录前的公开查看）。
- **自助账户注销（软删除）**：Regular User 可自助注销账户；注销后账户进入注销态、不可登录，个人身份信息匿名化、会话立即失效；以软删除方式保留合规与审计必要的数据。
- **关联数据处理**：注销时立即失效所有会话与已签发 Token、解绑 OAuth 第三方账号绑定、清除 TOTP 与 Passkey 二次认证凭据、联动取消生效中的订阅。
- **审计覆盖**：协议同意（注册/登录/重新同意）、协议版本发布/回退、账户注销操作均纳入审计日志。
- **前端交互**：注册页与登录页的同意选项与协议链接、协议查看页、个人中心注销入口与二次确认、Settings 协议 Tab（Realm Admin）。
- **多语言**：协议相关界面与协议文本通过既有 i18n 体系支持（en / zh-CN）。平台默认模板 seed 当前仅入库 `en` 正文初稿；`zh-CN` 正文待法务定稿后补充（i18n locale map 结构已就绪）。

### 2.2 不包含功能 (Out of Scope)

- 其他地区专项合规：CCPA（加州）、PIPL（中国）等地区差异化条款的专项适配，不在本轮范围。
- 数据可移植权（数据导出）：注销前的个人数据导出，后续扩展。
- 物理删除与宽限期：本次采用软删除（注销态 + 关键字段匿名化），不提供宽限期与自助恢复。
- Cookie 同意横幅：浏览器 Cookie 同意管理不在本轮范围。
- 一次性购买退款：一次性购买（积分包等）已交付的不予退款，属既定终止政策而非功能。
- Admin Realm 级全局协议工作台：不提供独立于 Settings Tab 的协议管理工作台。
- 协议正文的最终法律定稿：本轮提供平台默认模板初稿，正式定稿需法务审阅。
- 重大变更的差异化处理：本轮所有版本变更统一触发重新同意，不区分「重大/轻微」变更类型。

### 2.3 依赖项

- **用户认证与会话系统** — 提供登录态、会话失效能力。
- **Settings 页面与权限基础设施** — 复用 Settings 页面 Tab 与 `settings.view`/`settings.manage` 权限承载协议管理界面；协议正文与版本由专用版本表存储（不复用 `realm_config` KV，因其 upsert 无法承载 append-only 版本历史）。
- **Audit 审计日志** — 记录协议同意、版本变更、账户注销事件（复用既有统一审计模型）。
- **权限管理系统** — Realm Admin 协议管理的访问控制。
- **i18n 国际化** — 协议界面与文本多语言（en / zh-CN）。
- **OAuth / TOTP / Passkey** — 注销时的第三方绑定解绑与二次认证凭据清除。
- **订阅计费（subscription）** — 注销时联动取消生效中的订阅。

## 3. 需求概述

### 3.1 功能描述

为符合欧盟（GDPR）等地区对「知情同意」与「被遗忘权」的合规要求，Herald 需要补齐两块能力：

1. **协议与同意能力**：为用户协议与隐私政策提供承载、版本化与同意记录。协议采用「平台默认模板 + per-realm 覆盖」的作用域——平台维护默认模板（含可用的正文初稿），各 Realm 可覆盖为自有条款；用户协议与隐私政策各自独立版本化，每次发布产生新版本并留存历史，用户同意绑定具体版本；用户在注册与登录时即表示同意所属 Realm 当前生效版本，协议更新后需重新同意，且可随时查看。
2. **账户自助注销（软删除）**：允许 Regular User 自助注销账户。注销采用软删除：账户进入注销态且不可登录，个人身份信息被匿名化（不再可识别），同时保留账户骨架与合规、审计必要的最小数据；注销时立即失效会话、解绑第三方绑定、清除二次认证、联动取消生效中的订阅；一次性购买已交付的不予退款。

本能力是对现有用户生命周期（注册/登录/资料/退出登录）与既有 Realm Settings、Audit、Subscription 能力的合规性扩展，优先复用既有基础设施。

### 3.2 关键特性

- per-realm 协议版本管理（平台默认模板 + Realm 覆盖，专用版本表存储）
- 用户协议与隐私政策独立版本化，历史版本留存可追溯
- 同意记录可审计、与具体协议版本绑定
- 注册即同意、登录即同意、协议更新重新同意的三段式同意闸门
- 平台默认模板正文初稿（用户协议 + 隐私政策）
- 自助账户注销的软删除（匿名化 + 会话失效 + 关联数据清理 + 订阅取消）
- 协议同意、版本发布、账户注销全链路审计

## 4. 业务规则与状态

### 4.1 业务规则

**协议作用域**

- 协议采用「平台默认模板 + per-realm 覆盖」：平台维护默认模板；Realm 可覆盖为自有文本；Realm 未覆盖时回退到平台默认模板。
- 用户同意的是「所属 Realm 当前生效的版本」，同意记录与具体协议版本绑定。
- 协议文本按 Realm 隔离，Realm Admin 仅能管理本 Realm 协议。

**协议更新与版本管理**

- **独立版本化**：用户协议与隐私政策各自独立维护版本。
- **发布即新版本**：每次发布（Realm 发布/回退自定义，或平台默认模板更新）产生一个新版本，立即成为该 Realm 当前生效版本。
- **历史留存**：历史版本被保留，支持审计追溯用户在任一时间点同意的具体版本与时间。
- **版本变更触发重新同意**：Realm 发布/回退自定义、平台默认模板更新，均构成版本变更，已同意旧版的用户需重新同意。
- **更新感知**：已登录用户在下次登录或访问核心功能时感知更新并被要求重新同意；不强制中断用户进行中的非核心操作，但核心功能受同意闸门约束。
- **平台默认模板更新**：平台默认模板更新对未覆盖的 Realm 同样构成版本变更，触发其用户重新同意。
- **平台默认模板维护边界**：平台默认模板由受控数据库 seed/迁移或运维发布流程维护，当前 HTTP 管理 API 只管理指定 Realm 的草稿、发布与回退，不提供平台级默认模板写端点。

**同意规则**

- **注册即同意**：注册提交即表示用户同意所属 Realm 当前生效版本；注册页须提供协议查看链接。注册时的同意记录为 best-effort：版本查询或同意写入失败不阻断注册（仅记录警告、无同意记录），该用户在下次登录时按「登录即同意」规则被要求重新同意。
- **登录即同意**：登录时若用户同意缺失或版本已过期，用户随登录提交的同意被记录（Reconsent，绑定当前生效版本）；同意已是最新版本时，登录不产生新的同意记录。登录页须提供同意选项与协议查看链接。该规则覆盖全部登录入口，OAuth 直登（OAuth 回调直登分支、Google One Tap、Apple 原生登录、WeChat 直登）不豁免：命中闸门时直登入口不签发完整会话，而是返回 `consent_required: true` + 当前生效协议摘要 + 受限会话；因 provider 凭据一次性、无法携带同意重放登录，补全路径为：用户在受限会话下显式提交 `POST /api/legal/{realmId}/consent` 记录同意，然后重新触发该登录入口获取完整会话。
- **更新重新同意**：协议版本变更后，已同意旧版的用户需在登录或访问核心功能时重新同意。
- 用户拒绝同意最新版本时，无法继续使用需要同意的核心功能，但仍可退出登录或注销账户。
- 拒绝同意且没有可复用会话时，登录响应可签发只含资料读取、注销账户和退出登录 scope 的受限会话；该会话不能访问业务功能，但可完成二次认证后的自助注销，也可用于 OAuth 直登补全路径中的显式同意提交。
- 同意闸门的执行以前端路由守卫 + 后端 `consent/status` 查询驱动为主；后端对敏感端点的硬性拦截为 P1 可选增强，本期未实现。登录/注销端点不受同意闸门拦截（保障注销权不被剥夺）。
- 当前生效协议或同意状态查询发生存储故障时，同意闸门采取 fail-open 并记录告警，避免认证系统整体不可用；这是可用性取舍，不等同于写入同意记录成功。
- 已同意当前最新版本的用户不重复提示。

**软删除规则（账户注销）**

- 注销后账户进入「注销态」，不可登录。
- 注销后用户的个人身份信息（邮箱、昵称、密码等）被匿名化，不再可识别。
- 保留账户骨架与合规、审计必要的最小数据（如归属 Realm、账户标识、状态、时间戳）。
- 注销立即生效，无宽限期、不支持自助恢复。
- 注销时立即失效所有登录会话与已签发 Token；解绑 OAuth 第三方账号绑定；清除 TOTP 配置与 Passkey 凭据；联动取消生效中的订阅。
- 注销操作由用户本人发起，仅作用于自身账户。

**费用与终止规则**

- 一次性购买（如积分包等）已交付的不予退款；账户注销不触发一次性购买的退款。
- 生效中的订阅在注销时被联动取消，按订阅自身的取消与结算规则处理。

**审计规则**

- 协议同意（注册同意、登录同意与重新同意）、协议版本发布/回退、账户注销均记录审计事件。
- 审计遵循既有统一审计模型的 Realm 隔离与只读原则。
- 审计写入为 best-effort：主业务已经成功时，审计存储故障只告警、不回滚协议发布、回退、同意或注销；协议同意的事实真源仍是专用同意表，审计日志不是唯一存储。

### 4.2 关键状态与异常

- **账户状态扩展**：现有用户状态之外，新增「注销态」用于标识已注销账户；注销态账户不可登录，登录时被拦截。出于安全考量（避免账号存在性枚举），后端登录失败返回统一文案「email not verified or account not active」，不单独暴露注销态；前端可据此引导。
- **协议版本变更感知**：用户登录或访问核心功能时，系统按「用户已同意版本」与「Realm 当前生效版本」比较，存在差异时触发重新同意流程。
- **拒绝同意的边界**：拒绝同意不剥夺用户行使注销权——协议更新提示界面需同时提供退出登录与注销账户入口；无存活会话时使用登录返回的注销专用受限会话完成流程。
- **跨 Realm 协议访问**：Realm A 的用户/管理员无法查看或操作 Realm B 的协议；协议公开查看仅限对应 Realm。
- **匿名化与唯一性**：注销后个人身份字段匿名化需考虑邮箱唯一性约束的后续影响（注销后该邮箱能否重新注册属待确认项）。

## 5. 功能需求

### 5.1 核心需求

- **协议承载与版本**：平台提供默认模板（含正文初稿）；Realm 可覆盖；用户协议与隐私政策各自版本化；历史版本留存可追溯。
- **注册同意闸门**：注册表单提供协议查看链接；注册提交即表示同意当前生效版本；同意记录为 best-effort，失败不阻断注册（下次登录补记）。
- **登录同意**：登录表单提供同意选项与协议查看链接；同意缺失或版本过期时，随登录提交的同意被记录（Reconsent），同意已是最新版本时登录不产生新的同意记录。
- **重新同意闸门**：登录或访问核心功能时检测协议版本变更，触发重新同意；支持同意与拒绝两条路径；不强制中断进行中的非核心操作。
- **协议查看**：提供用户协议与隐私政策的查看入口（含登录后与注册/登录前的公开查看），展示版本信息。
- **协议版本管理**：发布产生新版本并立即生效；历史版本保留可查；Realm 发布/回退与平台默认模板更新均触发用户重新同意。
- **自助注销**：提供注销入口与二次确认；执行软删除（注销态 + 关键字段匿名化 + 会话失效 + 关联数据清理 + 订阅联动取消）。
- **Realm Admin 协议管理**：在 Settings 协议 Tab 查看当前生效协议（标识默认/自定义）、编辑并发布自定义版本、回退到默认模板；发布与回退产生新版本并留存历史。
- **审计**：覆盖协议同意（注册/登录/重新同意）、版本发布/回退、账户注销。

### 5.2 验收目标

- 用户在注册时通过同意选项确认才能完成注册，注册即同意被记录并与版本绑定（同意记录失败时注册仍成功，下次登录补记）。
- 用户登录时，若同意缺失或版本过期，通过同意选项确认后同意被记录（Reconsent）并绑定当前生效版本；同意已是最新版本时登录不产生新的同意记录。
- 协议版本变更（Realm 发布/回退或平台默认模板更新）后，已同意旧版的用户登录或访问核心功能时被提示重新同意；同意后可继续，拒绝则核心功能受限但可退出或注销。
- 协议版本变更不强制中断已登录用户进行中的非核心操作。
- 用户可随时查看所属 Realm 当前生效的用户协议与隐私政策及其版本信息。
- 历史协议版本可追溯，能证明用户在任一时间点同意的具体版本。
- Regular User 可自助注销账户；注销后账户不可登录、个人身份信息不可识别、会话立即失效、生效中订阅被取消，账户以软删除方式保留；一次性购买不予退款。
- Realm Admin 可管理本 Realm 协议（查看/发布自定义/回退默认），发布与回退产生新版本并触发用户重新同意；无法跨 Realm 操作。
- 协议同意、版本变更、账户注销均可在审计日志中查到。
- 所有操作在 Realm 隔离边界内完成。

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：
  - 协议查询（用户协议与隐私政策当前生效版本及版本信息，含公开查看）
  - 协议同意记录（注册同意、登录同意与重新同意，绑定具体版本）
  - 账户自助注销（仅作用于自身账户，联动取消生效中的订阅）
  - Realm Admin 协议管理（查看/发布自定义/回退默认，产生新版本）
- **访问控制原则**：
  - 协议公开查看无需登录。
  - 协议同意与账户注销为已登录用户的自身操作，业务逻辑层校验归属。
  - Realm Admin 协议管理需要本 Realm 的 Settings 管理权限。
- **Realm 数据边界**：协议文本、同意记录、注销操作均按 Realm 隔离，不可跨 Realm 访问或操作。
- **跨域联动**：注销触发订阅取消时，与计费域（subscription）按既定取消与结算规则协作，不绕过计费域约束。
- **审计要求**：协议同意、版本发布/回退、账户注销的接口调用需写入审计事件，遵循既有审计模型。
- **安全要求**：注销为不可逆敏感操作，需二次确认；同意记录与注销操作的归属校验不可绕过。
- 详细接口契约、验证规则与错误模型应在技术设计或接口文档中维护。

## 7. 前端/交互约束

**适用性**: 适用

- **注册页**：注册表单提供「我已阅读并同意《用户协议》《隐私政策》」同意选项（勾选或显式声明），协议名称为可点击链接（弹层或新页展示全文）；表达「注册即表示同意」语义；未确认同意时禁用提交并提示。
- **登录页**：登录表单提供同意选项与协议查看链接，表达「登录即表示同意《用户协议》《隐私政策》」语义；同意缺失或版本过期时，登录提交即记录同意（Reconsent）；已是最新版本时登录不产生新的同意记录。
- **登录/访问核心功能（协议更新）**：检测到协议版本变更时，展示协议更新提示与全文（含版本信息），提供「同意并继续」与「拒绝」两个路径；拒绝路径同时提供退出登录与注销账户入口；不强制中断进行中的非核心操作。
- **协议查看页**：个人中心提供「用户协议」「隐私政策」入口；注册/登录前提供公开查看入口；展示当前生效版本标识与生效日期。
- **注销入口与交互**：个人中心/安全设置提供「注销账户」入口；进入后需二次确认（如再次输入密码或显式确认提示），并在确认前明确告知：账户将被软删除、生效中订阅将被取消、一次性购买不予退款；完成后给出明确已注销反馈并跳转登录页。
- **Settings 协议 Tab（Realm Admin）**：在既有 Settings 多 Tab 布局中新增协议 Tab；展示当前生效协议并标识「平台默认模板 / 本 Realm 自定义」与版本信息；支持编辑发布自定义、回退默认；发布与回退提示将产生新版本并触发用户重新同意。
- **状态反馈**：注册未同意、登录同意、协议更新、注销成功/失败、协议发布成功等均有明确反馈。
- **权限可见性**：Settings 协议 Tab 仅 Realm Admin 可见；注销入口仅对登录用户可见。
- **多语言**：协议相关界面与协议文本通过既有 i18n 体系（en / zh-CN）呈现。

## 8. 已确认决策

- **目标域与定位**：归入 core 域，feature slug 为 `legal-consent-account-deletion`；范围为协议承载+同意记录与 Regular User 自助注销（软删除）。
- **协议作用域**：采用「平台默认模板 + per-realm 覆盖」；用户同意绑定所属 Realm 当前生效版本；协议正文与版本采用专用版本表存储（append-only，承载默认模板 + per-realm 覆盖 + 历史留存），复用 Settings 页面 Tab 与 `settings.view`/`settings.manage` 权限承载管理界面，不新建独立管理后台。
- **协议版本管理**：用户协议与隐私政策各自独立版本化；每次发布即产生新版本并立即生效；历史版本留存以供审计追溯；Realm 发布/回退与平台默认模板更新均构成版本变更并触发重新同意。
- **同意模式**：注册即同意 + 登录即同意 + 协议更新后重新同意，三段式闸门；同意记录与版本绑定并可审计。
- **软删除语义**：注销采用「标记注销态 + 关键字段匿名化 + 保留账户骨架与合规/审计最小数据」，立即生效、无宽限期、不可自助恢复。
- **关联数据处理**：注销时立即失效会话与已签发 Token、解绑 OAuth 绑定、清除 TOTP、联动取消生效中的订阅；一次性购买已交付的不予退款。
- **审计**：协议同意（注册/登录/重新同意）、版本发布/回退、账户注销均纳入既有统一审计模型。
- **平台默认模板正文**：本轮提供《用户协议》与《隐私政策》平台默认模板正文初稿，正式定稿需法务审阅。

## 10. 协议外部链接承载模式（2026-07 增量）

- Realm Admin 可分别为用户协议与隐私政策选择“站内全文”或“外部链接”，允许两份协议混合使用不同模式。
- 外部链接模式仅保存合法的 HTTP(S) URL，不抓取、缓存或本地化外部正文；链接最长 2048 字符，内容及可达性由 Realm Admin 负责。
- 模式和 URL 先保存为草稿，保存草稿不影响当前生效协议。发布草稿生成新的不可变版本，并沿用版本同意、重新同意和审计机制。
- 注册、登录、重新同意及个人中心入口在外部链接模式下于新标签页打开配置 URL；站内全文模式保持原有协议页。
- 全文与链接模式之间的切换属于版本变更并触发重新同意。仅修改链接草稿但不发布，不触发重新同意。
- 未配置租户链接时继续回退到平台默认全文协议。
