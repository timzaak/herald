# Realm Onboarding Guidance（自助开通强指引与管理员首登引导）产品需求文档 (PRD)

**创建时间**: 2026-10-04
**优先级**: P1
**所属域**: core

> 场景背景：自助开通 Realm 的能力（注册页、防滥用、平台开关、成功直达新 realm 控制台）已由 `docs/prd/core/realm-create.md` 交付，但平台门面登录页没有任何指向自助开通的入口，访客误注册为 admin realm 普通账号后即流失。本 PRD 在该能力前后补两个纯体验层：登录页自助开通强指引（曝光层）与 realm 管理员首次进入控制台的新手引导（首登体验层），不改变自助开通能力本身的任何语义。本文档不承载接口端点、请求/响应 schema、HTTP 状态码、数据库建表/迁移或代码类型定义；技术方案细节请参见对应技术设计。

## 2. 范围界定

### 2.1 包含功能

- **登录页自助开通强指引区块**（仅 admin realm 平台门面登录页）：平台价值主张摘要 + 「开通自己的 Realm」入口；区块显隐由平台自助开通开关决定（开启呈现；关闭、状态不可得或加载中不呈现，fail-closed），复用 realm-create 既有开关与其公开状态查询能力，不另设开关
- **登录页注册类入口分流**：signup 强指引为主区块，现存「注册普通账号(register)」链接降级为弱化的次级文字链接；admin realm 普通用户注册能力保持不变
- **realm 管理员首登新手引导三件套**（卖点导向）：营销式欢迎（平台卖点总述——权限模型、积分与钱包、支付收款、第三方登录对接、内置 MCP 服务；signup 直达路径与既有管理员路径使用不同欢迎文案变体）、新手任务清单（卖点导向的功能入口链接，控制台内持续可访问的重看入口）、控制台单页功能漫游（高亮侧边栏卖点功能区，折叠分组自动展开）
- **引导触发与完成态**：signup 成功直达、或管理员首次进入某 realm 管理控制台时触发；完成标记按 realm + 用户维度存于浏览器本地，完成或主动关闭后跨会话不自动重现
- **引导文案双语**：英文与简体中文（对齐既有界面语言集）

### 2.2 不包含功能 (Out of Scope)

- 自助开通后端语义的任何变更（鉴权、IP 限额、人机验证、开关存储模型——全部沿用 `docs/prd/core/realm-create.md`）
- 引导完成态的服务端存储与跨设备同步（本地存储及「换设备/清缓存重现一次」行为已作为产品行为接受；如需服务端记忆另行立项）
- 普通终端用户的首次登录引导（引导对象仅 realm 管理员）
- 跨页面/跨路由的连续功能漫游（漫游限定控制台单页，跨页引导由任务清单承接）
- 登录页既有登录表单逻辑与其他 realm 登录页（含 white-label 品牌化行为）的改动
- 线上启用平台自助开通开关的运营动作（属发布清单运营项，开关默认值决策归属 realm-create 的延期问题 Q-realm-create-003）
- 引导相关的后端事件上报、漏斗统计与转化分析
- 欢迎引导的视频等富媒体内容（欢迎弹窗为纯文案形态）

### 2.3 依赖项

- **realm 自助开通能力**（`docs/prd/core/realm-create.md`）— 强指引指向其托管于 admin realm 的注册页；区块显隐消费其平台开关的公开状态查询能力
- **管理控制台布局与 Dashboard**（`docs/prd/core/dashboard.md`）— 首登引导的承载面与任务清单卡片所在；漫游锚点为管理控制台布局侧边栏的卖点菜单项；引导不改变 Dashboard 既有指标内容与权限模型
- **界面国际化体系**（`docs/prd/core/i18n.md`）— 引导与 CTA 文案的双语承载

## 4. 业务规则与状态

### 4.1 业务规则

**入口与分流**

- 强指引区块**仅由 admin realm（平台门面）登录页承载**，非 admin realm 登录页不呈现——自助开通注册页由 admin realm 独家托管（DEC-realm-create-001），指引入口与其承载归属一致；其他 realm 的登录页面向各自租户用户，不承载平台级开通营销。
- 区块显隐规则：平台自助开通开关**开启时呈现**；**关闭、状态不可得或加载中时不呈现**（fail-closed），不向访客暴露任何「开关状态查询失败」类技术细节。复用 realm-create 既有开关与公开状态查询能力，不新增开关。
- **品牌化抑制**：admin realm 登录页处于 white-label 品牌覆盖（品牌名生效）时，平台强指引区块不呈现——品牌化的门面登录体验不混入平台营销内容，登录页其余功能不受影响。
- 「注册普通账号(register)」链接保留于 admin realm 登录页，但降级为弱化的次级文字链接（视觉与文案层级明显低于自助开通区块）；admin realm 普通用户注册能力（配置与注册端点）不变。
- 强指引入口对未登录访客可见，无需任何权限或登录前提。

**引导对象与触发**

- 引导触达对象**仅 realm 管理员**：signup 注册者（成功直达新 realm 控制台时）+ 首次进入任一 realm 管理控制台的管理员（含既有 realm 的管理员）；普通终端用户不触达。
- 引导由三部分组成，职责不重叠：营销式欢迎（平台卖点总述；signup 直达路径与既有管理员路径呈现不同欢迎文案变体，变体选择不影响是否触发）、新手任务清单（控制台内持续入口，清单内任务链接沿用与侧边栏一致的权限与功能开关可见性）、控制台**单页**功能漫游（高亮侧边栏卖点菜单项，锚点所在折叠分组自动展开且不产生导航）；跨页引导由任务清单承载，漫游不跨路由页。
- 引导是纯展示层：不新增权限、不改变任何管理功能的数据可见性，管理员既有权限模型完全不变。

**完成态与重现**

- 「已完成引导」标记按 realm + 用户维度存于浏览器本地存储。
- **完成或主动关闭**引导即写入完成标记；此后进入该 realm 控制台不再自动出现引导。
- 任务清单保留手动重看入口：用户可随时从清单重新发起功能漫游；重看不改写完成标记。
- 更换设备或清除浏览器数据导致标记缺失时，引导重新出现一次，用户可立即关闭——该重现行为已作为产品行为接受。

**多语言**

- 强指引与引导全部文案随界面语言呈现（英文/简体中文，对齐既有语言集），不引入新语言。

### 4.2 关键状态与异常

- **开关关闭/状态查询失败/加载中**：强指引区块不渲染；登录页其余功能（登录表单、register 链接等）正常。
- **品牌覆盖生效**：强指引区块不渲染；品牌化登录页其余功能正常。
- **引导组件异常**（漫游锚点缺失、引导内容加载失败、本地存储不可用）：引导降级（仅呈现欢迎与任务清单，或完全不呈现），**不得阻塞或破坏控制台任何管理功能的正常使用**。
- **完成标记缺失**（换设备/清缓存）：引导重现一次，可立即关闭。
- **非 admin realm 误达**：非 admin realm 访客不会看到平台自助开通指引（区块仅平台门面承载）；自助开通注册页对非开启状态的处理沿用 realm-create 既有规则。
- **signup 直达流程**：引导挂接在既有「signup 成功直达新 realm 控制台」流程之后，不改变直达行为与时序语义。

## 5. 验收目标

- 平台开关开启时，未登录访客在 admin realm 登录页看到自助开通强指引区块并可进入自助开通注册页；开关关闭或状态不可得时不渲染（US-OG-001 场景 1/2）
- register 以弱化次级链接呈现且注册能力不变；非 admin realm 登录页不受影响（US-OG-001 场景 3/4）
- admin realm 登录页品牌覆盖生效时，强指引区块不呈现，登录页其余功能不受影响
- signup 成功直达新 realm 控制台后引导呈现一次，文案跟随界面语言；完成或主动关闭后跨会话不自动重现；可从任务清单重看功能漫游（US-OG-002 场景 1~3）
- 引导内容围绕平台卖点：欢迎文案为卖点总述（含 MCP 一句提及），漫游高亮侧边栏的功能区入口（权限、支付、积分、钱包、设置-第三方对接），任务清单为卖点能力入口链接（US-OG-002 场景 1、US-OG-003 场景 1；DEC-realm-onboarding-guidance-008）
- 换设备/清缓存后引导重现一次且可立即关闭（US-OG-002 场景 4）
- 既有 realm 管理员首次进入控制台获得同形态引导，完成后同 realm 不再自动出现（US-OG-003）
- 引导组件任何异常不影响控制台管理功能正常使用（§4.2）
- 新增文案在两种界面语言下完整（无缺失键）

## 6. 边界与约束

**适用性**: 适用（API 与前端/交互边界合并陈述）

**API / 集成边界:**

- **接口能力范围**：纯前端交付，不新增、不修改任何后端接口与数据模型（含一个前端功能漫游组件依赖，选型见技术预研）。
- **能力消费**：强指引区块显隐消费 realm-create 已定义的「自助开通开关公开状态查询」能力（`docs/prd/core/realm-create.md` §6，未登录可查、仅返回布尔开放状态），不重复定义。
- **本地状态**：引导完成标记与欢迎文案变体信号均为浏览器本地状态，不产生任何后端调用。
- **口径沿用**：自助开通注册页的校验、防滥用（IP 限额、人机验证）与开关控制沿用 realm-create 既有规则，本 PRD 不改动其口径。

**前端 / 交互边界:**

- **页面入口**：admin realm 登录页（强指引区块挂载于既有认证页布局，不改登录表单逻辑）；realm 管理控制台（引导三件套承载面）。
- **关键交互**：强指引入口点击 → 自助开通注册页（既有页面，未登录可访问）；signup 成功 → 既有直达新 realm 控制台行为 → 控制台首次挂载触发引导；引导可关闭；任务清单可持续访问并重新发起功能漫游。
- **状态反馈**：开关关闭/状态不可得/品牌覆盖 → 区块静默不渲染（无错误提示暴露给访客）；引导组件异常 → 降级或不呈现，控制台功能不受影响。
- **权限可见性**：强指引无需登录；引导仅对已进入管理控制台的管理员呈现（进入控制台本身沿用既有控制台访问控制），不引入新权限项。
- **视觉与文案**：自助开通区块为主层级，register 链接为次级层级；漫游高亮样式与既有控制台主题一致；全部文案双语。

## 7. 已确认决策

> 本节只收录当前有效的决策与未决问题，记取舍、理由、决策人与重开条件；规则正文只在 §4 定义，DEC/Q 编号保持稳定，供代码注释、测试与跨 PRD 引用追溯。

- **DEC-realm-onboarding-guidance-001 · 登录页强指引**（user，2026-10-04）：admin realm 登录页新增「开通自己的 Realm」强指引区块，显隐复用平台开关（fail-closed），不另设开关（规则正文见 §4.1）。理由：2026-10-04 生产库实查：3/3 真实用户因登录页无引导，误在 admin realm 注册普通账号后一分钟内流失；用户明确要求对自助开通入口做强指引。落点：§2.1、§4.1、§5、§6。重开条件：用户要求移除登录页指引，或要求该区块由非 admin realm 门面承载。
- **DEC-realm-onboarding-guidance-002 · 首登营销式引导**（user，2026-10-04）：realm 管理员首次进入自己 realm 控制台时展示价值引导三件套，完成后跨会话不自动重现（规则正文见 §4.1）。理由：用户明确要求「首次登录自己的 realm 后有营销式引导说明核心功能与价值」；自助开通直达控制台后的空控制台是第二跳流失点。落点：§2.1、§4.1、§5。重开条件：用户要求取消首登引导或改变三件套形态。
- **DEC-realm-onboarding-guidance-003 · 入口分流策略**（user，2026-10-04）：signup 强指引为主，register 降级为弱化次级文字链接；普通注册能力不动（规则正文见 §4.1）。理由：用户在分流策略三选项中选择「signup 为主 + register 降级为弱链接」：保留普通注册可发现性，同时让自助开通在视觉与文案上占主导。落点：§2.1、§4.1、§5、§6。重开条件：线上仍持续出现误注册流失，需要彻底隐藏 register 链接或由运营关闭 admin realm 普通注册。
- **DEC-realm-onboarding-guidance-004 · 引导触达对象**（user，2026-10-04）：仅 realm 管理员（signup 注册者 + 首次进入任一 realm 控制台的管理员），不含普通终端用户（规则正文见 §4.1）。理由：与用户原始表述一致（引导围绕管理控制台核心功能与价值）；普通用户无管理控制台承载面，扩大属范围变更。落点：§2.2、§4.1、§5。重开条件：用户要求扩大到普通终端用户首登（属 PRD 范围变更，需重开）。
- **DEC-realm-onboarding-guidance-005 · 完成态存储**（user，2026-10-04）：完成标记浏览器本地存储（realm+用户维度），接受跨设备/清缓存重现一次；不新增后端存储（规则正文见 §4.1）。理由：后端无用户级偏好存储，为一次性漫游标记新建表/列/接口违反 Rule 2；用户确认接受该风险（对技术预研 D2 预裁决的用户确认）。落点：§2.1、§2.2、§4.1、§4.2、§6。重开条件：用户要求服务端记忆完成态（需重估技术路线）。
- **DEC-realm-onboarding-guidance-007 · 欢迎弹窗纯文案形态**（user，2026-10-04）：欢迎弹窗不内嵌视频等富媒体，纯文案形态承载价值说明。理由：用户判定该版营销视频素材质量不达标（2026-10-04 对话要求移除并同步调整 PRD/设计文档）。落点：§2.2。重开条件：出现任一质量达标的营销视频素材且用户要求重新内嵌（重新评估时参考 DEC-006 的位置结论：仅首登欢迎弹窗、CTA 不放）。
- **DEC-realm-onboarding-guidance-008 · 引导内容卖点导向**（user，2026-10-05）：漫游锚点从 Dashboard 首页元素（用户统计卡、认证趋势图、快捷导航）改为侧边栏卖点功能区（权限、支付服务商、积分账户、积分钱包、设置/第三方对接；锚点所在折叠分组自动展开，不产生导航），欢迎弹窗文案与任务清单条目同步卖点化（权限/积分/钱包/支付/第三方对接；MCP 因无控制台入口仅在欢迎文案提及）（规则正文见 §4.1）。理由：用户判定 Dashboard 首页元素引导无意义，引导应围绕平台卖点展开。落点：§2.1、§2.3、§4.1、§5。重开条件：用户要求恢复 Dashboard 页锚点，或控制台出现 MCP 入口页后将 MCP 纳入漫游。


> 本 PRD 无待用户回答的未决问题；跨 feature 影响决策（DEC-realm-create 系列）见 `docs/prd/core/realm-create.md` §7。
