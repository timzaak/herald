## 2. 范围界定

### 2.1 包含功能

- 前端 UI 文本国际化：所有硬编码的用户可见文本提取为可翻译资源
- 运行时语言切换：用户可在界面中切换语言，无需刷新页面
- 语言偏好持久化：用户选择的语言在浏览器关闭后保留
- 默认语言检测：根据浏览器语言设置自动选择界面语言
- 后端错误码标准化：后端 API 错误响应返回结构化错误码，前端按语言翻译
- 两套翻译文件管理：中文（zh-CN）和英文（en）的完整翻译资源

### 2.2 不包含功能 (Out of Scope)

- 后端文本翻译：后端不做 UI 文本翻译，仅返回错误码和英文描述（英文描述仅用于日志和调试）
- 数据库内容翻译：用户数据、Realm 名称、角色名称等业务数据不做翻译（例外：legal 协议正文按 locale 键控存储、读取时选取已存储正文，无运行时翻译——多语言由 legal 域自身的内容模型承载，见 legal-consent-account-deletion.md §2.1）
- 邮件模板翻译：邮件内容暂不纳入翻译范围
- 第三方语言：仅支持 en 和 zh-CN，不引入其他语言
- RTL（从右到左）布局支持：中文和英文均为 LTR 语言
- URL 本地化路由：不使用 `/-/en/` 或 `/-/zh-CN/` 前缀路径，语言切换不改变 URL 结构
- 服务端语言偏好存储：语言偏好仅存客户端，不持久化到数据库

### 2.3 依赖项

- 技术可行性研究：`.ai/tech-research/i18n-support.md` — 已完成，确认 Paraglide JS 与现有 Vite 插件链兼容
- 前端框架：React 19 + TanStack Router + Vite
- 后端现有错误结构：CoreError 枚举和 ErrorResponse 格式

## 4. 业务规则与状态

### 4.1 业务规则

- **默认语言检测**：首次访问时，系统读取浏览器语言设置；匹配 zh-CN 则显示中文，否则回退为英文
- **语言偏好存储**：用户选择的语言存储在浏览器 localStorage，跨会话保持
- **语言切换位置**：语言切换器位于侧边栏底部，提供中/英文切换入口
- **翻译范围界定**：仅翻译用户可见的 UI 文本；日志、技术标识符、代码内部字符串不翻译
- **错误码格式**：后端错误码使用 snake_case 格式（如 `not_found`、`permission_denied`；具体资源变体如 `user_not_found`、`realm_not_found`），前端翻译文件按错误码映射对应语言的提示文本；覆盖表单验证错误、操作失败提示、HTTP 错误等场景
- **不支持的语言回退**：浏览器设置为 en 或 zh-CN 以外的语言时，统一回退为英文
- **翻译 key 组织**：按模块分组（`common.*`、`auth.*`、`billing.*`、`users.*`、`settings.*`、`error.*`），确保命名一致

### 4.2 关键状态与异常

- **翻译缺失**：若某个 key 在当前语言的翻译文件中不存在，应回退到英文翻译（en 作为基础语言），不应显示 key 本身
- **错误码无对应翻译**：后端返回的错误码在前端翻译文件中无匹配时，显示通用错误提示文本
- **构建时验证**：翻译资源在构建时编译为类型安全的 TypeScript 函数（零运行时开销），key 变更会在编译时报错，防止运行时遗漏

## 5. 验收目标

1. 用户可通过语言切换器在中文/英文之间切换，切换后当前页面及后续导航的所有 UI 文本即时切换语言
2. 关闭浏览器后重新访问，语言偏好保持不变
3. 后端 API 返回的错误响应包含机器可读的错误码，前端按当前语言显示对应的错误提示
4. 所有管理后台页面和登录/注册页面无硬编码的未翻译文本
5. 翻译缺失时回退到英文，不显示原始 key

## 6. 边界与约束

**适用性**: 适用（API 与前端/交互边界合并陈述）

**API / 集成边界:**
- 后端 API 错误响应扩展，新增错误码字段（snake_case 格式），与现有错误消息并存；错误码不影响现有 API 契约的兼容性（`code` 字段在错误响应中始终返回，既有消费方可安全忽略）
- 语言偏好仅由前端和浏览器本地状态使用；后端当前不读取 `Accept-Language`，也不依赖请求语言做翻译或日志分类

**前端 / 交互边界:**
- **语言切换器位置**：侧边栏底部，显示当前语言标识（如 "EN" / "中"），点击切换
- **切换行为**：点击后立即切换当前页面所有文本，不需要页面刷新或重新导航
- **翻译覆盖范围**：导航菜单、页面标题、表格列头和操作按钮、表单标签和占位符、Toast 通知文本、确认对话框标题和内容、空状态提示文本、分页控件文本、搜索框占位符
- **不翻译的内容**：用户输入的数据（用户名、邮箱、角色名）、技术标识符（Realm ID、Client ID）、日志输出
- **登录/注册页面**：登录/注册页面的 UI 文本根据浏览器语言设置自动显示对应语言，不提供语言切换器

## 7. 已确认决策

- 目标语言仅 en 和 zh-CN，不引入其他语言 — 来源：用户原始需求
- 后端不做 UI 文本翻译，仅返回错误码 — 来源：技术可行性研究确认
- 语言偏好仅存客户端 localStorage — 来源：技术可行性研究确认
- 前端翻译方案选用 Paraglide JS — 来源：技术可行性研究推荐（TanStack Router 官方推荐方案）
- 不使用 URL 本地化路由 — 来源：本 PRD 决策（简化实现，两种语言无需 SEO 区分）
- 切换实现采用「运行时 setLocale(reload:false) + 根节点按语言 key 重挂载整树」兑现 §6 无刷新承诺（实现层）— 来源：实现决策（约 140 个组件直接调用 `m.*`，仅更新 context 无法让它们重渲染；重挂载会丢弃页面局部未保存状态，视为一次性切换动作的可接受代价）
- 所属域：core — 来源：PRD 澄清确认
